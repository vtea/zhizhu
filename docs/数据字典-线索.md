## 1. 文档范围

- **对象**：在 **[抖音企业号线索版后台](https://leads.cluerich.com/)** 经营视角下的 **「线索用户 / 高潜用户」** 等列表中的**单行用户**，在本系统 PG 中的**一条记录**（**线索实体**）。  
- **菜单**：主要服务 **「线索管理」**（概览 KPI、筛选、**未留资 / 已留资** Tab）；**数据大盘** 若展示线索聚合指标，须与本实体或派生汇总表同源，避免重复口径。  
- **不包含**：控制台 **平台用户**；抖音 **业务账号主数据**（见 **`数据字典-员工账号.md`**）；**视频逐条**（见 **`数据字典-视频.md`**）——仅可 **可选关联** 到视频。

---

## 2. 设计原则

1. **一行一线索用户**：以抖音侧可稳定对齐的 **主键** 去重，按 **未留资 / 已留资** 分列入 **`dy_lead_wlz_id` / `dy_lead_ylz_id`**（见 §3）；**禁止**仅用昵称+地区等易碰撞字段作唯一键。  
2. **归属链路**：与账号、视频一致，须带 **`tenant_id`** + **`dy_leads_enterprise_id`**（见 **`数据字典-员工账号.md` §2.5**）+ **`account_id`**（**来源/归属**抖音业务账号，即该用户出现在哪个矩阵账号的数据范围内）。写入与查询时校验 **主体 + 账号** 边界，**防跨租户 / 跨主体串数**。  
3. **`dy_` 前缀**：取自抖音后台或仅对抖音有意义的列（头像、昵称、意向等级码值等）使用 **`dy_`**；本系统指派类字段 **不加** `dy_`。  
4. **脱敏与上云**：凡涉及 **PII / 敏感画像** 的列须在 **`docs/脱敏白名单-上云字段.md`** 中显式列出分级与展示策略；**未批准字段不得写入 PG** 或须假名化（与立项书 §4.2、第 6 节一致）。  
5. **状态与 Tab**：**未留资 / 已留资** 与后台 Tab 对齐，以 **`lead_stage`** 与 **`dy_lead_wlz_id` / `dy_lead_ylz_id`** 分态支撑；**不** 另做「用户等级/意向」维度（**T05 已废**，见 **§3.3**），**不** 采本系统「**负责人/操作人**」落库（**T06 已废**，见 **§3.4**）。角标、筛选见 **§4**、**§6**。  
6. **「来源」与 `account_id` 的匹配、员工主数据更新**（**产品 2026-04-25**；与 **`数据字典-员工账号.md` §1 后 联动**）：  
   - **主路径**：`biz_account`（P2 企业员工号 / P3 个人号授权 汇总）**默认** 由用户在控制台 **【手动】点「更新」/「同步」** 拉通一次。  
   - **补缺**：在**落线索**或**展示**时，若某行 **「来源:」** 后的**抖音账户展示名** 在 **`biz_account` 中尚不存在** → **自动** 再执行一次**拉 P2、P3** 写库，再**按名** 匹配 `account_id`。  
   - **仍失败**：若**自动**拉完后 **仍** 对不上**来源**的展示名 → **提示用户检查**（名称是否**写错/改名/未入矩阵/见后台** 等），并**引导** 在 **「员工账号」** 中**核对或手动**维护。

## 3. 逻辑实体：`biz_lead`（示意表名）

### 3.1 主键与归属

| 物理列名 | 类型（示意） | 必填 | 说明 |
|----------|--------------|------|------|
| `id` | `uuid` | 是 | 本系统行主键 |
| `tenant_id` | `uuid` | 是 | 租户 |
| `platform` | `text` | 是 | 首版多为 `douyin` |
| `dy_leads_enterprise_id` | `text` | 是 | 企业号线索版主体，与 **`biz_account`** 同名字段一致 |
| `account_id` | `text` | 是 | **来源/归属**业务账号（`biz_account.account_id`） |
| `dy_lead_wlz_id` | `text` | 否* | **未留资**列表同步时的抖音侧线索/用户**稳定 id**；与 **`lead_stage=no_conversion`** 对应；*通常仅在该阶段有值。实现映射见 §7 |
| `dy_lead_ylz_id` | `text` | 否* | **已留资**列表同步时的抖音侧线索/用户**稳定 id**；与 **`lead_stage=converted`** 对应；*通常仅在该阶段有值。实现映射见 §7 |

\* **业务规则（产品 2026-04 起）**：**分 Tab 落两列**——在 **未留资** 抓到的行写 **`dy_lead_wlz_id`**，在 **已留资** 抓到的行写 **`dy_lead_ylz_id`**。接口中主取值优先 **`$.data.intentionUserList[*].clueId`**，**`id`** 仅**交叉**；**同一人** 从未留资 变为 已留资 时，两列/合并**是否**同一 `clueId`、**是否**合并**一行 PG**，**须**在对接时**再**对现网。  

**唯一约束建议**（以对接结论为准，示意）：`lead_stage` 为 **未留资** 时 **`(tenant_id, platform, account_id, dy_lead_wlz_id)`**；**已留资** 时 **`(tenant_id, platform, account_id, dy_lead_ylz_id)`**；或增加**可空** 辅助键 `dy_lead_key`（如 `coalesce(dy_lead_ylz_id, dy_lead_wlz_id)`）参与 **跨阶段** 去重。

## 6. 指标与概览 KPI

- **列表行级**：以 **`biz_lead`** 为主；**未留资/已留资条数** 等角标可由 **`COUNT(*) FILTER (WHERE lead_stage = …)`** 按 `tenant_id` + 筛选维度聚合。  
- **概览区 KPI**（如总线索、今日新增）：可用 **物化视图 / 按日汇总表**（示例 **`biz_lead_daily_agg`**），字段在详细设计中扩展，**须与** `biz_lead` **可核对**。
- **规则产物（来源映射口径）**：第二条 Playwright 规则可写入 **`biz_lead_source_daily_agg`**，粒度为 `stat_date + account_id`，仅保留 `no_conversion_count`、`converted_count`、`total_count` 三项及 `source_display_name`（用于来源对账）。

| 本字典概念 | 抖音侧实际字段/API/解析路径 | 备注 |
