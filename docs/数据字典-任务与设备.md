| 文档版本 | v0.3 |

---

## 1. 文档范围

- **设备**：Web「**设备绑定**」菜单与 Electron 客户端 **绑定码注册** 所对应的 **`biz_device`**（或等价表名）。  
- **任务**：Web「**系统设置 → 任务中心**」编排、下发至客户端执行的一条 **`biz_task`**；**执行流水**建议独立 **`biz_task_run`**（或 `biz_task_event`）便于审计与排障。  
- **自动化规则**：规则 **JSON/正文** 的存储与版本以立项书 **§4.1** 为准；本字典仅列 **与任务、设备关联的外键字段**（`rule_id` 等），**不**重复定义规则 DSL schema。

---

## 2. 全局约定

- **`device_id`**：云端与 WSS 会话识别的**设备实例**标识（建议全局唯一 UUID 或雪花 ID）；**不等于** `account_id`。  
- **任务与业务账号**：任务体须携带 **`tenant_id`**、**`dy_leads_enterprise_id`**（与 `biz_account` 一致）、**`account_id`**（执行目标抖音业务账号）、**`rule_id`**（可选）及 **运行时参数**（如日期范围）；由 **`数据字典-员工账号.md`** 校验账号有效。  
- **非敏感回传**：客户端上报任务状态仅 **结构化摘要**（进度、错误码、条数等），敏感原文见 **`脱敏白名单-上云字段.md`**。

| `device_label` | `text` | 否 | 备注名（如「张三办公机」） |

| `bound_by_user_id` | `uuid` | 否 | 发起绑定的平台用户 |

| `revoked_at` | `timestamptz` | 否 | 解绑时间 |
| `client_version` | `text` | 否 | 最近上报的客户端版本 |
| `created_at` / `updated_at` | `timestamptz` | 是 | |

**唯一约束建议**：`(tenant_id, device_id)`。

### 3.0.1 HTTP：客户端凭绑定码登记设备（与 `apps/api` 一致）

用于 **Electron 等无浏览器 JWT** 的场景：安全依赖 **`biz_device_bind_code`** 单次有效、过期时间与熵（`BIND-` 前缀 + hex，见 `issueBindCode`）。

| 项 | 说明 |
|----|------|
| **路径** | `POST /api/v1/device-bind/consume` |
| **鉴权** | 无 Bearer；**勿**将绑定码写入日志明文字段 |
| **请求体 JSON** | `code`（必填；**`BIND-<hex>` 大小写不敏感**，服务端与客户端会规范为大写再查库）、`device_label`（可选，写入 `biz_device.device_label`） |
| **成功 201** | `{ "ok": true, "tenant_id": "<slug>", "device_id": "<新 device_id>" }`；并 `INSERT biz_device`、`UPDATE biz_device_bind_code.used_at`、写 `biz_device_audit` |
| **失败 400** | `{ "error": "<原因>" }`（无效码、已使用、已过期、唯一约束冲突等） |

Web 控制台在租户上下文下发码：`POST /api/v1/tenants/:tenantId/device-bind-codes`（需 JWT）。校验码（不消费）：`POST /api/v1/device-bind-codes/verify`。

## 3.1 逻辑实体：`biz_device_browser_account`（设备上的「线索版浏览器配置」与账号）

**目的**：云端要知道 **哪台 `device_id` 上** 为 **哪条 `biz_account`（抖音业务账号）** 维护了 **哪一套持久化浏览器用户数据**（与客户端 `PLAYWRIGHT_BROWSER_PROFILE` / `userDataDir` 子目录 **slug 一致**），以及 **该浏览器里登录态是否仍有效**（未掉线），便于排障、任务路由与审计。

| 物理列名 | 类型（示意） | 必填 | 说明 |
|----------|--------------|------|------|
| `id` | `uuid` | 是 | 主键 |
| `tenant_id` | `uuid` | 是 | 租户 |
| `device_id` | `text` | 是 | FK 语义 → `biz_device.device_id` |
| `account_id` | `text` | 是 | 执行目标 **`biz_account.account_id`**（与任务、员工账号字典一致） |
| `browser_profile_slug` | `text` | 是 | 客户端目录/profile 名（**仅小写字母数字连字符**，与 `tools/playwright-field-probe` 约定一致）；**一台设备上** slug 唯一 |
| `registered_at` | `timestamptz` | 否 | 客户端首次上报该绑定的时间 |
| `last_reported_at` | `timestamptz` | 否 | 客户端最近一次上报本行（含健康探测结果）的时间 |

**唯一约束建议**：`(tenant_id, device_id, browser_profile_slug)`。

## 3.2 会话健康：`session_health`（由客户端探测上报，云端只读展示）

**语义**：表示 **该 profile 对应浏览器上下文里**，线索版（或依赖的 SSO）是否仍处于 **可执行业务** 的登录态，**不是** `biz_device.last_seen_at`（后者只表示 WSS 设备在线）。

| 取值（建议枚举） | 含义 |
|------------------|------|
| `healthy` | 最近一次探测成功（例如命中需登录态的接口返回 200，或 DOM/路由表明已在工作台内） |
| `stale` | 超过 `check_ttl` 未探测，**未知**是否仍登录（设备在线但探测未跑或失败重试中） |
| `logged_out` | 探测明确发现登录墙、401/302 至 SSO、或业务侧「未登录」错误码 |
| `unknown` | 设备离线、或从未完成过该 profile 的探测 |

**推荐列（可并入上表或独立 `biz_device_browser_account_health`）**：

| 物理列名 | 类型（示意） | 必填 | 说明 |
|----------|--------------|------|------|
| `session_health` | `text` | 是 | 上表枚举 |
| `last_session_check_at` | `timestamptz` | 否 | 最近一次完成探测的时间 |
| `last_session_good_at` | `timestamptz` | 否 | 最近一次判定为 `healthy` 的时间 |
| `session_check_error_code` | `text` | 否 | 非敏感错误码（如 `LOGIN_WALL`、`HTTP_401`），**禁止**存 Cookie / 响应体原文 |

**探测节奏（产品约定，非必选列）**：

- **客户端**：在 **设备在线** 且 **无高优先级采集任务** 时，按 **固定间隔**（如 5～15 分钟，可配置）对每个已绑定 `browser_profile_slug` 执行 **轻量探测**（headless、短超时）：打开约定入口 URL 或请求已知需登录态的 API，将结果压缩为 `session_health` + `session_check_error_code` 经 **WSS 或 REST 心跳附带字段** 上报。  
- **服务端**：持久化上列时间戳；Web「设备绑定」列表可 **轮询或订阅** 展示；**禁止**由服务端代持用户 Cookie 去代测（避免合规与串号风险）。

## 6. 与 Playwright / 解析字段的关系

- **任务不直接存页面解析结果**；解析结果进入 **`biz_lead` / `biz_video` / `biz_account`** 等事实表，并受 **`脱敏白名单-上云字段.md`** 约束。  
- **Playwright 定稿后**：在规则或任务模板中固化 **URL、选择器、接口 URL pattern**；本字典不展开，见 **§4.1.1** 与后续 **规则 schema** 文档（若单独拆分）。

## 7. 实现映射（工程必填）

| 概念 | 说明 |
|------|------|
| `device_id` 生成策略 | *待填*（建议：绑定成功时服务端签发全局唯一 ID 并写入客户端本地配置） |
| WSS 会话与 `device_id` 绑定 | **见 §8**：连接鉴权通过后，服务端将 socket 会话与 `(tenant_id, device_id)` 绑定；断线重连须重新鉴权 |
| `status` 状态机 | *待填*（`biz_task.status` 与客户端回执 `task.run.*` 对齐） |
| `biz_device_browser_account` 与任务 `payload.browser_profile_slug` | 任务若指定 profile，客户端必须使用该目录启动 `launchPersistentContext`；绑定表用于控制台展示「哪台机挂了哪个号」 |
| `session_health` 上报 | **见 §8.2、§8.4**：优先 **WSS** `device.browser_session.report`；可选在 **`device.heartbeat`** 的 `payload.browser_sessions` 中批量附带（减少消息数） |

## 8. WSS 消息契约（客户端 ↔ 服务端）

**传输**：`wss://`（TLS 上的 WebSocket），**每条消息**为 **UTF-8 JSON 文本帧**（单帧一条 JSON，首版不规定二进制分片）。

**方向**：

- **上行** `client → server`：心跳、绑定登记、会话健康、任务回执。  
- **下行** `server → client`：握手应答、任务下发、取消指令。

**安全**：

- 连接建立时携带 **设备凭证**（建议：`Sec-WebSocket-Protocol` 承载 token，或连接后首条 `device.hello` 内 `device_token`，具体以网关实现为准）；**禁止**在日志中打印 token 全文。  
- 服务端校验通过后，将连接登记为 **`device_id`** 对应会话，并刷新 **`biz_device.last_seen_at`**（与 **§3** 一致）。

---

### 8.1 通信封套（必填字段）

所有消息均包含下列 **顶层字段**（下行同理）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `schema_version` | `int` | 是 | 本契约版本；首版固定 **`1`** |
| `msg_id` | `string` (uuid) | 是 | 发送方生成的消息 ID，用于去重与应答关联 |
| `type` | `string` | 是 | 消息类型，见 **§8.2**（上行）、**§8.3**（下行） |
| `tenant_id` | `string` (uuid) | 是 | 租户 |
| `device_id` | `string` | 是 | 设备业务 ID，须与绑定一致 |
| `sent_at` | `string` | 是 | ISO-8601 UTC，如 `2026-04-23T12:00:00.000Z` |
| `payload` | `object` | 条件 | 各 `type` 的载荷；无载荷时可为 `{}` |

**应答关联（可选）**：下行消息可带 `correlation_msg_id`，指向客户端此前上行的 `msg_id`（例如对 `task.dispatch_ack` 的应答）。

---

### 8.2 上行消息类型（`type`）

| `type` | 用途 | `payload` 要点 |
|--------|------|----------------|
| `device.hello` | 连接就绪后首包（或重连后）：上报客户端版本、OS 摘要 | `client_version`，`os`（非敏感），可选 `capabilities[]` |
| `device.heartbeat` | 周期性存活；可嵌套浏览器会话摘要 | `interval_sec`（客户端计划心跳间隔）；可选 **`browser_sessions`**（数组，元素结构见 **§8.4**） |
| `device.browser_account.upsert` | 登记或更新「本机某 profile 对应哪条业务账号」 | `browser_profile_slug`，`account_id`；首次登记驱动 **§3.1** 表 |
| `device.browser_session.report` | 某 profile 完成一次轻量探测后的结果 | 单条 **§8.4** 对象（建议放在 `payload.session`） |
| `task.dispatch_ack` | 已收到任务下发 | `task_id`，`accepted`（bool），`reject_code`（可选，非敏感） |
| `task.run.progress` | 任务执行进度 | `task_id`，`percent` 或 `phase`，`message`（非敏感） |
| `task.run.completed` | 任务成功结束 | `task_id`，`result_summary`（JSON，非敏感，与 **§4** 一致） |
| `task.run.failed` | 任务失败 | `task_id`，`error_code`（非敏感），`message`（非敏感） |

---

### 8.3 下行消息类型（`type`）

| `type` | 用途 | `payload` 要点 |
|--------|------|----------------|
| `device.hello_ack` | 握手成功 | `server_time`；可选 `heartbeat_interval_sec`（服务端建议心跳间隔） |
| `task.dispatch` | 下发可执行任务 | `task_id`，`account_id`，`dy_leads_enterprise_id`，可选 **`browser_profile_slug`**，可选 `rule_id` / `rule_version`，`payload`（运行时参数，**不得**含明文 PII） |
| `task.cancel` | 取消进行中任务 | `task_id`，`reason_code`（非敏感） |

---

### 8.4 `BrowserSessionPayload` 对象（`browser_sessions[]` 元素与 `payload.session` 共用）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `browser_profile_slug` | `string` | 是 | 与 **§3.1** 一致 |
| `account_id` | `string` | 是 | `biz_account.account_id` |
| `session_health` | `string` | 是 | 枚举见 **§3.2** |
| `last_session_check_at` | `string` | 否 | ISO-8601 UTC，完成探测时间 |
| `last_session_good_at` | `string` | 否 | 最近一次判定为 `healthy` 的时间 |
| `session_check_error_code` | `string` \| `null` | 否 | 非敏感错误码 |
| `check_interval_minutes` | `number` | 否 | 客户端计划探测间隔（分钟） |

### 8.8 REST 备选（非实时场景）

若客户端暂时无法维持 WSS，允许 **HTTPS POST** 上报与 `device.heartbeat` / `device.browser_session.report` **同构的 JSON 体**（路径由 API 网关定义，如 `POST /api/v1/devices/{device_id}/telemetry`），服务端归一写入与 WSS 相同字段。**任务下发仍以 WSS 为主**（或配合客户端短轮询，产品另议）。
