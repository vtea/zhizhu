# 数据字典：自动化规则

> 与 [`docs/立项计划书-企业线索采集与分析平台.md`](立项计划书-企业线索采集与分析平台.md) §4.1 保持一致；规则 DSL 单一事实源在 [`packages/playwright-rule-schema`](../packages/playwright-rule-schema)。

## 1. 表速览

| 表 | 维度 | 写入权限 | 备注 |
|---|---|---|---|
| `biz_automation_rule` | 每条 rule_id 一行（已发布 / 官方草稿） | 租户 JWT 单边写；设备 token 仅可读 published | 立项 §4.1.1；migration 021 |
| `biz_automation_rule_device_draft` | (tenant_id, rule_id, device_id) | 设备 Bearer 写本设备草稿；租户 JWT 可读、promote、改写或删除设备草稿 | migration 032，本次新增 |
| `biz_rule_dispatch_log` | 规则下发审计 | 租户 JWT + 内部进程 | migration 021；本次扩 `event_type` 枚举 |
| `biz_lead_source_daily_agg` | 规则产出的线索日汇总事实表 | 仅设备 Bearer 通过 `/runner/file-rule-ingest` 写入 | migration 036；`mapping.target=lead_source_daily_agg` |

## 2. `biz_automation_rule_device_draft`（新表）

```sql
CREATE TABLE biz_automation_rule_device_draft (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id text NOT NULL,
  rule_id text NOT NULL,         -- 与 biz_automation_rule.rule_id 关联，但不强制 FK
  device_id text NOT NULL,
  name text NOT NULL,
  body jsonb NOT NULL DEFAULT '{}',
  base_version text,             -- fork 时记录的 published 版本号
  base_pulled_at timestamptz,
  schema_version int NOT NULL DEFAULT 1,
  updated_at timestamptz NOT NULL DEFAULT now(),
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (tenant_id, rule_id, device_id),
  -- FK biz_device(tenant_id, device_id) ON DELETE CASCADE
  CONSTRAINT chk_pwrule_draft_body_size CHECK (octet_length(body::text) < 262144)
);
```

- **rule_id**：可与 `biz_automation_rule.rule_id` 同名（fork 现有规则）或新建（纯本地规则）。客户端写入时校验 `^[A-Za-z0-9_\-:.]{4,128}$`。
- **base_version**：客户端 fork 时记录的 published 版本；Web 管理员 promote 后写入 bumpPatch 版本号。
- **乐观锁**：API PUT 接受 `expected_updated_at`；远端已变更则 409 让客户端先 pull。
- **body schema_version**：与 `RULE_SCHEMA_VERSION_MAX` 同步，未来升级时由 [`packages/playwright-rule-schema/src/index.ts`](../packages/playwright-rule-schema/src/index.ts) 单点维护。

## 3. RuleBody DSL（v1）

详细字段见 [`packages/playwright-rule-schema/src/index.ts`](../packages/playwright-rule-schema/src/index.ts)；步骤集合：

| step.type | 关键字段 | 占位符 |
|---|---|---|
| `goto` | `path` 或 `url`，可选 `waitUntil` | — |
| `setDateRange` | `field_locator: SelectorRef`、`start`、`end`、可选 `separator` | `{{start_date}}` `{{end_date}}` |
| `clickTab` | `name` | — |
| `click` | `selector: SelectorRef`、可选 `times` | — |
| `paginate` | `mode: 'next_button' \| 'scroll'`、`limit_pages`、可选 `next_button_selector / scroll_pixels / step_wait_ms` | — |
| `collectTable` | `row_selector`、`columns: [{ key, selector, attr?, default? }]`、可选 `also_write_captures / max_rows` | column.selector.value 内 |
| `captureResponse` | `url_pattern`、`key`、可选 `url_pattern_is_regex / json_path` | — |
| `wait` | `ms` 或 `selector` 或 `response_key`（恰一项），可选 `timeout_ms` | — |

`SelectorRef` ：

```ts
{ kind: "role" | "testid" | "css", value: string, name?: string, fallbacks?: SelectorRef[] }
```

链式降级：`getByRole` → `getByTestId` → `locator(css)`。**禁止 raw eval / 字符串脚本**。

## 4. API 路由速览

### 4.1 设备 Bearer（来自客户端 RunnerLoop / IDE）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/v1/tenants/:tid/runner/automation-rules` | 列租户已发布规则（设备只读） |
| GET | `/api/v1/tenants/:tid/runner/automation-rules/:rid` | 读单条 published body（404 若非 published） |
| GET | `/api/v1/tenants/:tid/runner/automation-rule-drafts` | 列本设备所有草稿 |
| GET | `/api/v1/tenants/:tid/runner/automation-rule-drafts/:rid` | 读单条本设备草稿 |
| PUT | `/api/v1/tenants/:tid/runner/automation-rule-drafts/:rid` | upsert 草稿（带 `expected_updated_at` 乐观锁） |
| DELETE | `/api/v1/tenants/:tid/runner/automation-rule-drafts/:rid` | 删除本设备草稿 |

### 4.2 租户 JWT（来自 Web 控制台）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/v1/tenants/:tid/automation-rules-device-draft-counts` | 列每条 rule_id 下的设备草稿数（列表页提示） |
| GET | `/api/v1/tenants/:tid/automation-rules/:rid/device-drafts` | 列本规则下所有设备草稿（含 device_label） |
| PUT | `/api/v1/tenants/:tid/automation-rules/:rid/device-drafts/:device_id` | 租户管理员改写某设备的草稿（载荷与 Runner PUT 一致，含乐观锁） |
| DELETE | `/api/v1/tenants/:tid/automation-rules/:rid/device-drafts/:device_id` | 租户管理员删除某设备的草稿副本 |
| POST | `/api/v1/tenants/:tid/automation-rules/:rid/device-drafts/:device_id/promote` | 把某设备草稿写入 `biz_automation_rule.body`（status 维持 draft） |

## 5. `biz_rule_dispatch_log` 事件枚举（扩展）

| `event_type` | 触发 | `payload` 关键字段 |
|---|---|---|
| `dispatched`（既有） | Web → 设备下发 | — |
| `draft_promoted_from_device`（**新增**） | Web admin Promote 设备草稿 | `from_device_id`、`base_version`、`new_version`、`promoted_by` |

后续若加 `published` / `draft_pushed_by_device` 事件，请同步本表与 [`apps/api/src/automationRuleDraftSync.ts`](../apps/api/src/automationRuleDraftSync.ts) 的 INSERT 语句。

## 6. 客户端持久化（与 API 一致的 mirror）

- `userData/automation-rules.json`：`{ published: PublishedRuleCacheEntry[], drafts: DeviceDraftEntry[] }`
- `userData/automation-rule-sync-status.json`：`AutomationRuleSyncStatus`（`lastPullOkAt / lastPushOkAt / conflictCount` 等）
- `userData/automation-rule-runner-status.json`：`RunnerLoopStatus`（最近一次任务、当前任务等）
- `userData/rule-trace/<run_id>.zip`：试跑 trace；不上云。

详细类型见 [`apps/client/src/automationRules.ts`](../apps/client/src/automationRules.ts) 与 [`apps/client/src/automationRuleSync.ts`](../apps/client/src/automationRuleSync.ts)。
