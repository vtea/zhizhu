# 实施计划：租户授权、平台登记与控制台开号

本文档描述**目标业务逻辑**（含与当前实现的差异）、**判定顺序**与**数据库 / 前端命名**，颗粒度到可对照写测试用例。实现时以本文为准迭代代码。

---

## 1. 核心概念（避免混在一起的点）

| 概念 | 落库位置 | 管什么 |
|------|----------|--------|
| **平台租户登记** | `biz_platform_tenant` | 这家客户在平台侧的「名片 + 授权」：显示名、备注、**控制台用户上限**、**服务周期**、**是否冻结**等。 |
| **控制台登录账号** | `biz_console_user` | 具体某个人能否登录：用户名、邮箱、密码哈希、角色。同一 `tenant_id` 下多行 = 多个登录用户。 |

**结论**：

- **登记租户 ≠ 自动拥有可登录用户**；没有 `biz_console_user` 行，任何人都无法以该租户身份登录。
- **登录名 / 邮箱 / 密码**属于用户表，**不**放在 `biz_platform_tenant`。
- **当前用户数**不落库，始终按 `biz_console_user` 中该 `tenant_id` 行数统计。

---

## 2. 角色与入口（谁做哪件事）

| 角色 | 典型 tenant_id | 能做的事（目标状态） |
|------|----------------|----------------------|
| **平台管理员** | `zhizhuplatform`（保留租户） | 全站租户列表、登记/编辑 `biz_platform_tenant`（含 **续期 / 解冻**）、在租户 **未冻结且未到期** 时为业务租户 **创建控制台用户**（开号）、调用 `/api/v1/admin/...`。 |
| **业务租户管理员** | 如 `demo`、`acme` | 在本租户内业务功能、组织成员里**带登录账号**的开号（第二人及以后），受席位与租户状态约束。 |
| **保留租户** | `zhizhuplatform` / 历史 `__platform__` | 仅承载平台管理员账号；**不参与**业务租户席位与到期策略（应用层豁免）。 |

## 3. 业务规则（编号便于评审与测试）

### 3.1 自助注册（与当前代码差异）

**目标**：生产环境 **不开放** 公开自助注册。

| 规则 ID | 内容 |
|---------|------|
| BR-REG-01 | `POST /api/v1/auth/register` 在未允许时返回 **403**（或 404，由产品定），错误信息明确为「未开放自助注册」类文案，**不**创建用户。 |
| BR-REG-02 | 允许开关建议为环境变量（如 `CONSOLE_ALLOW_PUBLIC_REGISTER=true` 仅开发/内测）；**未设置或为 false 时拒绝**。 |
| BR-REG-03 | Web 登录页**不展示**注册入口（与 API 一致）。 |

**说明**：当前仓库中注册接口仍可能可用；上线前须与 BR-REG-01～03 对齐。

---

### 3.2 新租户如何出现「第一个能登录的人」（闭环）

**目标**：不依赖自助注册时，**必须由平台侧**写入第一条 `biz_console_user`。

| 规则 ID | 内容 |
|---------|------|
| BR-FIRST-01 | 平台管理员在登记或编辑租户后，可通过 **`POST /api/v1/admin/tenants/:tenantId/console-users`**（名称可微调，须仅 `platform_admin`）创建该租户下控制台用户，角色含租户管理员。 |
| BR-FIRST-02 | 若该租户 **`max_console_users` 已配置** 且当前人数 **≥ 上限**，则**拒绝**创建（含首账号），返回明确业务错误（如「已达控制台用户上限」）。 |
| BR-FIRST-03 | **到期或冻结时**：该租户下 **任何人都不能登录**（见 BR-AUTH-01、BR-AUTH-02）；**平台也不能**通过代开号接口新增 `biz_console_user`；组织成员「带登录」、（若开放的）自助注册 **同样不得** 新增控制台用户。**续期**（将 `service_end_at` 延至未来）或 **解冻**（`tenant_status = active`）之后，才允许 **开号** 与 **登录**。不单独保留「到期后仍允许平台救急开号」分支。 |

---

### 3.3 席位（控制台用户上限）

| 规则 ID | 内容 |
|---------|------|
| BR-SEAT-01 | **计数口径**：`count(*) FROM biz_console_user WHERE tenant_id = :tid`（与是否组织成员无关，以登录账号行为准）。 |
| BR-SEAT-02 | **`max_console_users` 为 NULL**：表示**不限制**席位（仍可能受冻结/到期限制登录，见 3.4）。 |
| BR-SEAT-03 | **`max_console_users` 为整数 N 且 N ≥ 1**：在**任意**新增控制台用户前（平台开号、组织成员带登录、若将来恢复注册）执行：若 `当前人数 >= N`，则 **拒绝** 并返回「已达授权席位数，请联系升级」类文案。 |
| BR-SEAT-04 | **保留租户** `zhizhuplatform`（及兼容的旧名）：**不**对平台管理员账号做席位拦截（避免锁死全站）。 |

---

### 3.4 冻结与服务到期（登录拦截）

| 规则 ID | 内容 |
|---------|------|
| BR-AUTH-01 | **`tenant_status = suspended`（已冻结）**：该租户下**所有**控制台用户**禁止登录**（保留租户豁免见 BR-SEAT-04 / 下表）。 |
| BR-AUTH-02 | **`service_end_at` 非空且当前时刻 &gt; `service_end_at`**：视为服务已到期，该租户下**禁止登录**（保留租户豁免）。 |
| BR-AUTH-03 | **`service_end_at` 为空**：不据此刻做「到期」判断。 |
| BR-AUTH-04 | **冻结与到期同时配置**：满足**任一**即禁止登录。 |
| BR-AUTH-05 | **登录校验顺序（推荐）**：① 校验用户名/密码；② 密码正确后，再读取该租户在 `biz_platform_tenant` 的授权行（若无行，见 3.5）；③ 判断保留租户豁免；④ 判断 `suspended`；⑤ 判断 `service_end_at`；⑥ 写登录审计、签发 JWT。顺序用于统一错误码与审计；**对外错误文案**是否区分「账密错误」与「租户已停用」由产品定（安全与客服体验权衡）。 |
| BR-AUTH-06 | **新增控制台用户**（平台开号、组织带登录、注册）时，**与登录共用**「未冻结且未到期」判定（及 3.5 无登记行策略）；不满足则 **拒绝创建**，与 BR-FIRST-03 一致，引导先 **续期 / 解冻**。 |

---

### 3.5 仅有业务数据、无 `biz_platform_tenant` 行的租户

列表接口对业务侧出现过的 `tenant_id` 会做 **LEFT JOIN**，可能出现「有用户或业务表数据，但从未平台登记」的行。

| 规则 ID | 内容 |
|---------|------|
| BR-EDGE-01（**已采用**） | 无平台登记行时，视为 **`max_console_users`、服务周期均未配置**：**不**据此刻拦截登录与加人（兼容历史库）。无平台行的租户须在管理页 **补登记** 后才可「编辑」授权字段。 |
| BR-EDGE-02（未采用） | 无平台登记行时，**禁止**新增控制台用户，直至补登记；若将来需要可再实现。 |

---

### 3.6 登录成功后的到期提醒（可选）

| 规则 ID | 内容 |
|---------|------|
| BR-NOTICE-01 | 在**仍允许登录**的前提下，登录响应可携带 `tenant_notice`（如 `service_end_at`、`days_remaining`），前端顶栏 Banner 展示。 |
| BR-NOTICE-02 | 阈值（如剩余 ≤14 天提醒）仅为展示策略，**不改变** BR-AUTH-02 的到期判定。 |

## 4. 数据库字段与前端展示名称

### 4.1 表 `biz_platform_tenant`

| 数据库字段名 | 类型（建议） | 前端展示名称 |
|--------------|--------------|--------------|
| `tenant_id` | `text` PK | 租户 ID |
| `display_name` | `text` | 显示名 |
| `note` | `text` | 备注 |
| `created_at` | `timestamptz` | 登记时间 |
| `max_console_users` | `integer`，可 NULL | 控制台用户上限 |
| `service_start_at` | `timestamptz`，可 NULL | 服务开始时间 |
| `service_end_at` | `timestamptz`，可 NULL | 服务到期时间 |
| `tenant_status` | `text` | 租户状态（`active`→**正常**，`suspended`→**已冻结**） |
| `updated_at` | `timestamptz` | 最后更新时间 |
| `updated_by` | `text`，可 NULL | 最后更新人 |

**派生（不落库）**

| 逻辑名 | 前端展示名称 |
|--------|--------------|
| `current_console_users`（或统一命名 `console_user_count`） | 当前用户数 |

列表建议展示 **当前用户数 / 上限**，例如 `2 / 3`；无上限时 `2 / —`。

### 4.2 平台「创建控制台用户」表单（写入 `biz_console_user`）

| 数据库字段名 | 前端展示名称 |
|--------------|--------------|
| `login_username` | 登录用户名 |
| `email` | 邮箱 |
| `display_name` | 姓名 |
| 密码（仅请求体，哈希入库） | 初始密码 |
| `roles` | 首账号默认租户管理员时，可界面只读展示 **角色** |

## 5. API 与 JSON 命名

- 与现有控制台 API 风格一致，建议使用 **snake_case** 与数据库对齐。
- 建议新增：
  - `PATCH /api/v1/admin/tenants/:tenantId` — 更新平台登记与授权字段。
  - `POST /api/v1/admin/tenants/:tenantId/console-users` — 平台为指定租户创建控制台用户（首账号与后续代开）。

## 6. `service_end_at` 语义（须产品定一条）

| 模式 | 含义 | 实现要点 |
|------|------|----------|
| 日历日（常见） | 如「北京时间 2026-05-01 当天仍可用，次日不可」 | 应用层把运营选择的日期转为该自然日**结束瞬间**（约定时区如 `Asia/Shanghai`）再写入 `timestamptz`。 |
| 精确时刻 | 合同约定的具体 UTC 时刻 | 直接存该时刻，`now() > service_end_at` 即到期。 |

选定后，在管理端日期控件与 README 中写死，避免运营与工程理解不一致。

## 7. 实施任务清单（研发）

1. **迁移**：为 `biz_platform_tenant` 增加授权相关列；种子行 `zhizhuplatform` 保持可登录（`tenant_status`、`service_end_at`、`max_console_users` 语义与豁免一致）。
2. **API**：扩展 `GET /api/v1/admin/tenants`；实现 `PATCH`；实现平台 `POST .../console-users`；实现 `CONSOLE_ALLOW_PUBLIC_REGISTER`（或等价）关闭注册。
3. **校验复用**：冻结、到期、（及 3.5）无登记行策略抽公共函数；**新增用户**与 **登录** 共用同一套租户状态判定（BR-FIRST-03、BR-AUTH-06）；再叠加席位（BR-SEAT-03）。供 `loginConsoleUser`、平台开号、组织成员开号、（若开启）注册共用。
4. **Web**：租户管理列表与编辑；平台开号表单；登录页按开关隐藏注册；可选全局到期 Banner。
5. **测试**：合同测试覆盖 BR 规则；修改 `apps/web` 后执行仓库根 `npm run test:e2e`（见 `AGENTS.md`）。
