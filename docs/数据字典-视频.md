## 1. 文档范围

- **对象**：抖音侧 **单条短视频/视频** 在本系统中的一行记录（**视频实体**）。  
- **菜单**：主要服务 **「视频管理」**、**「推荐视频」**；与 **「数据大盘」** 中视频类模块共用同一主键与指标源时，须避免重复建表。  
- **不包含**：账号主数据（见 **`数据字典-员工账号.md`**）、线索自然人明细（见 **`数据字典-线索.md`**）。  
- **关联（易混）**：按视频、运营手填的**投放/投前/金额** 等 见 [**`数据字典-视频投放-示意.md`**](数据字典-视频投放-示意.md)（`biz_ad_placement`）；**与** 本表 **热** 指标 **不是** 同一时序，**禁止** 用 **`biz_video` 最新** 赞评藏转 **覆盖** 该表已落库的**投前**基线（见该字典 **§0、§3**）。

---

## 2. 设计原则

1. **一行一视频**：每条视频独立存储，**不**把发布列表序列化进 **`biz_account`**。  
2. **归属链路**：**租户** → **企业号线索版主体**（`dy_leads_enterprise_id`，定义见 **`数据字典-员工账号.md` §2.5**）→ **业务账号**（`account_id`）→ **视频**（`dy_video_id` 等）。其中 **`dy_leads_enterprise_id` + `account_id`** 须与 **`biz_account`** 一致；写入任务回传时须校验，**防跨主体串数**。  
3. **`dy_` 前缀**：抖音专有或可溯源抖音的列使用 **`dy_`**（与员工账号字典约定一致）。  
4. **指标时效**：播放量、赞评藏转等**随时间变化**的指标，建议 **`biz_video` 存当前展示快照** + **`biz_video_daily_stat`（或等价名）存按日/按同步批次历史**；详细设计二选一或并存。

### 2.1 公网 URL 与 `dy_video_id`（C 端与 BFF 对账）

- **同一条** 抖音 Web 视频，在公网常有两种入口，**主键是同一串数字**（**即** 本表 **`dy_video_id`**，存为**字符串** 即可）：  
  1. **用户页 + 弹层**：`https://www.douyin.com/user/{userPath}?modal_id={视频数字ID}` —— 查询参数 **`modal_id`** 的取值 **即** `dy_video_id`。  
  2. **纯视频页**：`https://www.douyin.com/video/{视频数字ID}` —— 路径中 **紧接** `/video/` 的段 **即** 同一 `dy_video_id`（[规范外链形态](https://www.douyin.com/video/) 以**该**路径为准，分享/外跳**推荐**用本式，**不** 用整段 `user/...?...` 作「唯一主键」存储）。  
- **企业号线索版** 或 **矩阵/账号侧** 后台经 **BFF** 返回的**视频 id**（P6 等 XHR，**见 §6**）与上列 **C 端数字** **须** 对为**同一**；**不得** 将 `userPath`、整段公网 URL 与 `dy_video_id` 混为同一列。  
- 若业务**只**拿到长链：解析时**只取** `modal_id` 或 `/video/` 后**第一段** 数字，写入 **`dy_video_id`**；`v.douyin.com` 等**短链**形态可后续补解析，**首版** 以 **`modal_id` + `/video/{id}`** 为准。  
- **对本文档的示例**：勿在 `docs/` 中粘贴**可追踪** 的**完整**公网长链作生产样例，可用占位符 **`{dy_video_id}`** 表述。

## 3. 逻辑实体：`biz_video`（示意表名）

| 物理列名 | 类型（示意） | 必填 | 说明 |
|----------|--------------|------|------|
| `id` | `uuid` | 是 | 本系统行主键 |
| `tenant_id` | `uuid` | 是 | 租户 |
| `platform` | `text` | 是 | 首版多为 `douyin` |
| `dy_leads_enterprise_id` | `text` | 是 | 与 **`biz_account.dy_leads_enterprise_id`** 一致，**企业号线索版侧企业/商家主体**固定标识，便于按主体筛选与校验 |
| `account_id` | `text` | 是 | 所属抖音业务账号，FK 语义至 **`biz_account`**（`tenant_id`,`platform`,`account_id`） |
| `dy_video_id` | `text` | 是 | 抖音侧（**C 端/公网** 与 **线索版·矩阵 BFF**）的**同一条**视频**数字 id** 字符串；与 **`?modal_id=`、 `/video/`** 路径段及 **P6 列表 JSON** 中视频 id **对账**；见 **§2.1、§6**（**不可** 用整段公网长链、仅标题当主键） |
| `dy_title` | `text` | 否 | 标题/话题文案，可变 |
| `dy_cover_url` | `text` | 否 | **封面图** URL（列表缩略图；须为可直链展示的图片地址） |
| `dy_video_url` | `text` | 否 | **视频页** URL（如 `v.douyin.com` 短链、`/video/{id}` 等）；与 `dy_cover_url` 分列 |
| `dy_duration_sec` | `int` | 否 | 时长（秒） |
| `dy_publish_at` | `timestamptz` | 否 | 发布时间（抖音侧） |
| `dy_play_count` | `bigint` | 否 | 播放量等当前快照 |
| `dy_like_count` | `bigint` | 否 | 点赞 |
| `dy_comment_count` | `bigint` | 否 | 评论 |
| `dy_favorite_count` | `bigint` | 否 | 收藏 |
| `dy_share_count` | `bigint` | 否 | 分享/转发 |
| `dy_completion_rate` | `numeric` | 否 | 完播率等，若可采集 |
| `dy_lead_count` | `int` | 否 | 线索量等，若可采集 |
| `metric_synced_at` | `timestamptz` | 否 | 当前快照同步时间 |
| `created_at` | `timestamptz` | 是 | 首次入库 |
| `updated_at` | `timestamptz` | 是 | 最近更新 |

**唯一约束建议**：`(tenant_id, platform, dy_video_id)`；若抖音侧 ID 在主体下不全局唯一，则改为 **`(tenant_id, dy_leads_enterprise_id, dy_video_id)`**（以对接结论为准）。

## 4. 与 `biz_account` 的关系

- 每条 **`biz_video`** 的 **`account_id`** 必须在同 **`tenant_id`** 下存在对应 **`biz_account`** 行。  
- **`dy_leads_enterprise_id`** 应与该 **`biz_account`** 上字段**相等**；若 **`biz_account`** 上主体变更（极少见），须级联修正或触发数据修复任务。

---

## 5. 与「推荐视频」及「视频投放」

- **推荐视频**：**推荐分**可在 **`biz_video`** 上增列 `recommend_score`、`recommend_formula_version`，或独立 **`biz_video_recommend_snapshot`**；**同一 `dy_video_id`** 不得维护两套矛盾的赞评藏转基数。  
- **视频投放**：单条视频的**运营投放/预算/投前基线** 见 [**`数据字典-视频投放-示意.md`**](数据字典-视频投放-示意.md)。**`biz_video`** 存**当前**互动快照；**投前** 在 **`biz_ad_placement`** 为**录入当刻**基线，**不得**与 **`dy_like_count` 等** 混列、**不得**用本表**最新同步**自动改写该基线。
